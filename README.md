# GH-900-GitHub-Foundations-Practice-Questions-A-Guide-to-the-Official-Exam-Outline
GitHub Foundations is a beginner-level certification for people who want to show that they understand how to work and collaborate on GitHub. It is not limited to software developers. The GH-900 study guide includes Git basics, repositories, pull requests, project tracking, security, modern development tools, and the GitHub community. If you use GitHub at work or are learning to contribute to a project, the exam gives you a clear list of concepts to practice.

## GH-900 exam overview

- **Certification:** GitHub Foundations.
- **Level:** Beginner.
- **Assessment time:** 100 minutes.
- **Delivery:** Proctored; scheduled through Pearson VUE.
- **Languages listed:** English, Spanish, Portuguese (Brazil), Korean, and Japanese.
- **Passing score:** 700 or higher, according to the study guide's scoring information.

The study guide presents seven skill areas as of January 2026. Its percentages are ranges, so they should guide preparation without being treated as a fixed number of questions.

## The seven official skill areas

### Understand Git and GitHub basics (25-30%)

Start with the purpose of version control and the difference between Git and GitHub. Know what a repository, commit, and branch represent. Then connect those terms to GitHub accounts, organizations, enterprise options, and GitHub Flow. The guide also names Markdown in issues and pull requests, plus suitable uses for GitHub Desktop and GitHub Mobile.

### Work with GitHub repositories (10-15%)

Study the repository files a new contributor will encounter: README, LICENSE, CONTRIBUTING, CODEOWNERS, and SECURITY. Practice creating and maintaining a repository, adding files, and using templates and branches. The outline also includes repository insights, stars, feature previews, metrics dashboards, and dependency insights.

### Collaborate using GitHub (10-15%)

Issues, pull requests, and discussions have different jobs. Practice deciding which one fits a request, then link a pull request to an issue and use templates, filters, assignments, and notifications. Review when Gists, Wikis, or GitHub Pages would help a team share information.

### Apply modern development practices (10-15%)

The guide covers GitHub Actions, GitHub Copilot, Codespaces, dev containers, and github.dev. Know the purpose of each tool and where its boundaries are. For Copilot, the listed scope includes code suggestions, agents, Agent Mode, multi-model support, and the differences among Individuals, Business, and Enterprise plans.

### Manage projects with GitHub (5-10%)

Review GitHub Projects layouts, labels, milestones, workflows, assignees, and saved replies. Project insights are also listed. Try organizing a small set of sample issues so these features become decisions rather than vocabulary items.

### Understand privacy, security, and administration (10-15%)

Study account security with two-factor authentication and passkeys. Distinguish repository and organization roles, visibility options, branch protection, teams, and organization settings. The guide also names Enterprise Managed Users and organization-wide Copilot policy management.

### Explore the GitHub community (5-10%)

Understand open-source participation, GitHub Sponsors, following people and organizations, GitHub Marketplace, and InnerSource. Know when a fork, template, or discoverable repository helps collaboration.

## A practical GH-900 preparation sequence

First, create a small practice repository and make a few commits on a branch. Add a README and a CONTRIBUTING file, then open an issue and a pull request. That one exercise connects Git fundamentals, repository management, Markdown, and collaboration.

Next, explore Projects, notifications, and repository settings. Compare an account-level security choice with a repository-level permission. Finally, review Actions, Copilot, Codespaces, and the wider GitHub community at the conceptual depth described in the study guide.

## Six final preparation tips

1. Use the current GH-900 study guide rather than an older topic list.
2. Give Git and GitHub basics enough time; it has the largest published range.
3. Practice a complete branch, issue, and pull request workflow in a repository you control.
4. Compare tools that sound similar, such as github.dev and Codespaces.
5. Review security choices at the account, repository, and organization levels.
6. Recheck the certification page before booking the exam.
